# 故障记忆闭环

## 目标

故障记忆用于复用已经验证过的排障经验，但历史案例不能替代当前故障证据。

## 入库条件

一条故障记忆必须同时具备：

1. 明确的故障现象与影响服务。
2. 来自日志、指标、告警或人工验证的关键证据。
3. 经值班人员确认的根因。
4. 实际执行过的处置动作。
5. 证明业务恢复的验证结果。

Agent 自动生成的诊断报告只能作为复盘草稿。未经人工确认的猜测、待验证假设和失败处置不能写入故障记忆库。

## 后续故障中的使用边界

检索到的故障记忆统一标记为“历史相似案例”。历史案例可以帮助提出排查方向和查询语句，但不能证明当前故障具有相同根因。

诊断报告引用历史案例时必须：

- 明确标注案例编号和“历史案例”身份。
- 使用当前告警、指标和日志独立验证。
- 说明当前证据与历史案例的一致点和冲突点。
- 当前证据不足时将根因标记为待验证假设。

## 错误记忆处理

如果复盘结论后来被证明错误，应从故障记忆界面删除该记录。删除操作会同时移除 SQLite 审计记录和 Milvus 向量，防止错误经验继续影响诊断。
